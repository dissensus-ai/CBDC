## 0. Honesty rules

1. Do not optimize experiments to obtain equivalence.  
2. Report regimes where identity-linked auxiliary information **improves** detection as prominently as regimes where it does not.  
3. Do not treat AUC or AP equivalence as operational equivalence.  
4. Do not call synthetic attributes “civil identity access.”  
5. Do not equate one boosted-tree implementation with detector capability generally.  
6. Entity linkage / stable cluster IDs are surveillance even without names.  
7. The earlier AUC=1 failure remains a methodological contribution.  
8. Confirmatory analyses are fixed below; all else is exploratory unless amended in writing.  
9. Generator/gate failures are reported, never silently redrawn.  
10. Existing pilot runs (including seed 20260707) are **development only**, not confirmatory.

**Registration language:** **pre-specified**. Not “pre-registered” unless a public timestamped registry exists before confirmatory runs.

## 1. Construct validity (required)

### 1.1 What the tiers actually expose

Aligned with `detection/features.py` column sets:

| Tier | Label (use in protocol & eventual manuscript) | Features | What is **not** exposed |
|------|-----------------------------------------------|----------|-------------------------|
| **T2** | **Linked behavioural features** | Entity-level aggregates over an entity/cluster map (wallet counts, velocity, internal flow, chain pass-through, etc.) | Civil name, government ID, full KYC dossier |
| **T3** | **Selected KYC/contextual attributes** | T2 + `kyc_tier`, `account_age_days`, `prior_sar_count`, `jurisdiction_risk` | Raw civil identity documents or identifiers |
| **T4** | **Watchlist indicator** | T3 + `on_watchlist` bit | Full watchlist contents; raw identity |

### 1.2 Measured construct

**Primary measured construct:**

> **Identity-linked auxiliary information above entity linkage** — the incremental detection value of selected KYC/contextual attributes and/or a watchlist indicator, holding linked behavioural features fixed.

**Not measured:**

- Access to raw civil identity (name, national ID, biometrics, full dossier).  
- Lawful intercept or compelled production of identity.  
- Human investigator skill with identity documents.

### 1.3 Language rules

| Forbidden (unless heavily qualified) | Allowed |
|--------------------------------------|---------|
| “civil identity access” as the experimental treatment | “identity-linked auxiliary information (KYC/context attributes, watchlist bit)” |
| “deanonymization to real names” as what T3/T4 do | “attachment of selected non-behavioural attributes / watchlist status to the linked entity” |
| “identity is useless for AML” | “in this DGP, selected auxiliary attributes add little / much under model M and budget k” |

### 1.4 Estimand notation

Let \(M(\cdot)\) be an endpoint (operational or secondary).  

- **Auxiliary block A3:** selected KYC/contextual attributes (T3 ∖ T2 features).  
- **Auxiliary block A4:** watchlist indicator (T4 ∖ T3 features).  
- **Full auxiliary block A:** A3 ∪ A4 (T4 relative to T2).

Primary operational contrast uses **T2 vs T4** (full auxiliary block above linked behaviour).

**Rule:** Until the “Author choice” column is completed and dated by Murad (and Andrew where noted), \(k^\*=50\) and \(\delta^\*=1\) are **illustrative defaults for design discussion only**, not scientific constants justified by pilot data.

### 2.2 Numerical implications at 5% prevalence (illustrative \(k^\*=50\), \(n=10{,}000\))

Assume \(p=0.05\) → expected \(N^+ = 500\) illicit entities on the test population.

| Quantity | Formula / implication |
|----------|------------------------|
| Reviews | \(k=50\) entities inspected |
| Max achievable recall | \(50/500 = 0.10\) if all 50 alerts are true positives |
| Missed illicit if perfect TPs | \(500-50=450\) → MissedPer10k \(= 450\) (floor set by budget, not model) |
| If T4 has \(\mathrm{TP}=40\), T2 has \(\mathrm{TP}=38\) | \(\Delta_{\mathrm{miss}} = 10000\times(40-38)/10000 = 2\) additional misses for T2 vs T4 |
| \(\delta^\*=1\) meaning | T2 may deliver at most **one fewer true positive among the top-50** than T4 (equivalently ≤1 extra miss per 10k) before failing illustrative equivalence |
| Stringency | At 10% max recall, a 1-TP gap is **tight** relative to sampling noise — authors may raise \(\delta^\*\) or \(k\) after **non-confirmatory** workload consultation, not after peeking at confirmatory \(\Delta_{\mathrm{miss}}\) |

These implications **motivate discussion**; they do **not** justify the placeholders scientifically.

## 3. Endpoint definitions (realised labels)

### 3.1 Setup per replicate \(r\)

1. Generate **independent training population** \(\mathcal{D}^{\mathrm{tr}}_r\) of size \(n_{\mathrm{train}}\).  
2. Generate **independent test population** \(\mathcal{D}^{\mathrm{te}}_r\) of size \(n_{\mathrm{test}}=10{,}000\).  
3. For each model \(m\) and tier \(T \in \{\mathrm{T2},\mathrm{T3},\mathrm{T4}\}\) (and T1 only if pre-specified):  
   - **Retrain** \(m\) from scratch on \(\mathcal{D}^{\mathrm{tr}}_r\) using only features allowed under \(T\).  
   - Score all entities in \(\mathcal{D}^{\mathrm{te}}_r\).  
4. **No** pooling of train and test.  
5. **No** global ranking of cross-validation OOF scores for confirmatory endpoints.  
6. Degeneracy audit: run on training population (and optionally report test-side diagnostics without using them to tune).

### 3.2 Alert selection

On the test set of size \(n = n_{\mathrm{test}}\):

- Let \(k = k^\*\) when \(n=10{,}000\) (exact map: \(k = k^\* \cdot n / 10{,}000\)).  
- Select the set \(S_T\) of \(k\) test entities with highest scores under tier \(T\) (ties broken by pre-specified rule: lower entity_id wins).

### 3.3 Realised counts

Let \(N^+ =\) number of test entities with illicit label \(Y=1\).  
Let \(\mathrm{TP}_T = |\{ i \in S_T : Y_i = 1 \}|\).

\[
\mathrm{MissedPer10k}(T)
  = 10000 \times \frac{N^+ - \mathrm{TP}_T}{n}
\]

With \(n=10{,}000\):

\[
\mathrm{MissedPer10k}(T) = N^+ - \mathrm{TP}_T
\]

(missed illicit entities on that test population, scaled as “per 10k” by construction).

**Recall at budget:** \(R@k(T) = \mathrm{TP}_T / N^+\) (undefined if \(N^+=0\); discard replicate only under documented rare-event rule — prefer regenerating whole train+test pair under amendment if \(N^+=0\)).

### 3.4 Paired contrasts and signs (unambiguous)

All contrasts are **within the same replicate** \(r\) (same train/test draws for all tiers/models being compared).

| Symbol | Definition | Sign interpretation |
|--------|------------|---------------------|
| \(\Delta_{\mathrm{miss}}^{\mathrm{T2}-\mathrm{T4}}(m)\) | \(\mathrm{MissedPer10k}_{m}(\mathrm{T2}) - \mathrm{MissedPer10k}_{m}(\mathrm{T4})\) | **Positive** ⇒ T2 misses **more** illicit entities than T4 (auxiliary info helps) |
| \(\Delta_{\mathrm{miss}}^{\mathrm{T2}-\mathrm{T3}}(m)\) | \(\mathrm{MissedPer10k}_{m}(\mathrm{T2}) - \mathrm{MissedPer10k}_{m}(\mathrm{T3})\) | Positive ⇒ KYC/context attributes reduce misses vs linked behaviour only |
| \(\Delta_{\mathrm{miss}}^{\mathrm{T3}-\mathrm{T4}}(m)\) | \(\mathrm{MissedPer10k}_{m}(\mathrm{T3}) - \mathrm{MissedPer10k}_{m}(\mathrm{T4})\) | Positive ⇒ watchlist bit reduces misses beyond T3 |
| \(\Delta_{\mathrm{TP}}^{\mathrm{T4}-\mathrm{T2}}(m)\) | \(\mathrm{TP}_{m,\mathrm{T4}} - \mathrm{TP}_{m,\mathrm{T2}}\) | Positive ⇒ T4 recovers more true positives in the top-\(k\); equals \(\Delta_{\mathrm{miss}}^{\mathrm{T2}-\mathrm{T4}}\) when \(n=10k\) |

**Primary operational estimand (confirmatory C1):**

\[
\Delta_{\mathrm{miss}} \equiv \Delta_{\mathrm{miss}}^{\mathrm{T2}-\mathrm{T4}}(\mathrm{L3})
\]

**Illustrative equivalence (pending author \(\delta^\*\)):**  
Evidence that \(\Delta_{\mathrm{miss}} \le \delta^\*\) under the replicate-level interval procedure (§6).

**Surveillance-superior (auxiliary info helps beyond tolerance):**  
Evidence that \(\Delta_{\mathrm{miss}} > \delta^\*\).

### 3.5 Secondary endpoints (not used to set \(\delta^\*\))

- AP and AUC on the **test population only** (scores from train-fit model).  
- Precision@\(k\).  
- Calibration (Brier/ECE) on test.

**Forbidden:** deriving an AP TOST margin from pilot scores and promoting it to primary.

## 4. Evaluation design (replaces OOF global ranking)

### 4.1 Per-replicate algorithm (normative)

```
for r in 1..R:
  seed_r = SEED0 + r   # or from prespecified seed list
  D_tr ← Generate(seed_r, role=train, n=n_train)
  D_te ← Generate(seed_r + SEED_OFFSET, role=test, n=10000)
       # independent RNG stream; no shared entities
  audit ← DegeneracyAudit(D_tr)
  if audit fails: log failure; do NOT silent-redraw (§6)
  for m in {L3, L0, ...}:
    for T in {T2, T3, T4}:
      fit m_T on D_tr with feature set T
      score D_te
      compute TP, MissedPer10k, AP, AUC
  compute paired Δ_miss within r
```

### 4.2 Why not confirmatory OOF

Entity-disjoint CV OOF rankings mix fold structure into a single list and understate deployment shift between independently generated populations. Confirmatory claims use **train population → test population** generalisation.

### 4.3 T1 (if reported)

T1 remains wallet-level features. Any entity-level metric that max-pools wallets using the **true** entity map is **T1-oracle-eval** (benchmark only), not an operational unlinked detector output.

## 5. Confirmatory claims and multiplicity

### 5.1 Headline claim policy

**Chosen policy for v3 freeze candidate:**

Keep the substantive hypothesis that **model class moderates the value of identity-linked auxiliary information**, but only as a **confirmatory difference-in-differences (DiD)** with hierarchical testing — not as a free-floating slogan.

### 5.2 Primary model-by-tier DiD estimand

For each replicate \(r\):

\[
\begin{aligned}
\Delta_{\mathrm{miss},r}^{\mathrm{L3}}
  &= \mathrm{MissedPer10k}_{r,\mathrm{L3}}(\mathrm{T2})
   - \mathrm{MissedPer10k}_{r,\mathrm{L3}}(\mathrm{T4}), \\
\Delta_{\mathrm{miss},r}^{\mathrm{L0}}
  &= \mathrm{MissedPer10k}_{r,\mathrm{L0}}(\mathrm{T2})
   - \mathrm{MissedPer10k}_{r,\mathrm{L0}}(\mathrm{T4}), \\
\mathrm{DiD}_r
  &= \Delta_{\mathrm{miss},r}^{\mathrm{L0}} - \Delta_{\mathrm{miss},r}^{\mathrm{L3}}.
\end{aligned}
\]

**Interpretation of \(\mathrm{DiD}_r > 0\):**  
The miss reduction from adding auxiliary information (T2→T4) is **larger for logistic (L0)** than for boosted trees (L3) — i.e. auxiliary information substitutes more for the linear model.

Across replicates, report \(\overline{\mathrm{DiD}}\) and a **percentile interval** \([L_{\mathrm{DiD}}, U_{\mathrm{DiD}}]\) over \(\{\mathrm{DiD}_r\}\).

### 5.3 Hierarchical testing (confirmatory family)

Order (gatekeeping):

| Step | Claim | Decision rule (illustrative \(\delta^\*\) pending approval) |
|------|--------|---------------------------------------------------------------|
| **H1 (primary ops)** | L3 operational effect of auxiliary block | Interval for \(\overline{\Delta}_{\mathrm{miss}}^{\mathrm{L3}}\) vs \(\delta^\*\): equiv if \(U \le \delta^\*\); superior if \(L > \delta^\*\); else inconclusive |
| **H2 (moderation)** | Model capacity moderates auxiliary value | Only if H1 is reported (any of the three verdicts); then test whether \(L_{\mathrm{DiD}} > 0\) (L0 benefits more than L3). If H2 fails, **drop headline “capacity conditions…”** and report DiD as inconclusive |
| **H3 (descriptive)** | L0 \(\Delta_{\mathrm{miss}}\) magnitude | Always tabulated; **no** equivalence claim required |

**Multiplicity:** H1 is not Bonferroni-diluted. H2 is tested only after H1 is completed (gatekeeping). All phase diagrams, prevalence grids, T2-resolved grids, AP tables = **exploratory** (no stars).

### 5.4 Alternative (if authors reject H2)

If authors choose **not** to stake a headline on moderation:

- Delete H2 from confirmatory family.  
- L0 is **descriptive only**.  
- Manuscript may **not** claim “model capacity conditions the value…” as a confirmatory result.

Record choice in author decision table.

## 6. Replicates, seeds, pilots, gate failures

### 6.1 Excluded Monte Carlo pilot (sets \(R\))

1. Freeze all constants except \(R\).  
2. Run \(R_{\mathrm{pilot}}\) replicates with seeds from list **PILOT_SEEDS** (e.g. 900001–900020).  
3. **These seeds and their data are excluded from confirmatory analysis forever.**  
4. Estimate \(\mathrm{SD}\) of \(\Delta_{\mathrm{miss},r}^{\mathrm{L3}}\) from the pilot.  
5. Choose \(R\) so that the half-width of a 90% normal-approximation CI for the mean is ≤ **precision target** \(\tau\) (author-chosen; illustrative \(\tau = 0.5\) missed entities per 10k).  
   \[
   R \ge \left\lceil \left(\frac{z_{1-\alpha/2}\,\widehat{\mathrm{SD}}}{\tau}\right)^2 \right\rceil
   \]
6. Record \(R\), \(\widehat{\mathrm{SD}}\), \(\tau\), and formula in a dated pilot note.  
7. Confirmatory seeds = **CONF_SEEDS** of length \(R\), disjoint from pilot (e.g. 20260805 + \(r\)).

### 6.2 Prespecified seeds

Publish in protocol lock file:

- `SEED_OFFSET` for test stream.  
- Full `PILOT_SEEDS` and `CONF_SEEDS` lists.  
- Library version pins.

### 6.3 Gate / generator failures — no silent redraw

| Event | Action |
|-------|--------|
| Degeneracy audit fail on train | Log `FAIL_AUDIT`, seed, worst feature, AUC; **count as failed replicate**; do **not** replace seed |
| Degeneracy fail rate > pre-set threshold (e.g. >10% of attempted) | **Stop**; diagnose DGP; **protocol amendment** before continuing |
| \(N^+=0\) or \(N^+=n\) on test | Log `FAIL_LABEL`; count failed; no silent redraw |
| Numerical crash | Log `FAIL_NUM`; count failed |
| Confirmatory analysis set | All successful CONF_SEEDS; report failure table with rates |

**Never** draw a new seed to replace a failed one without a written amendment that redesigns the generator or audit threshold.

### 6.4 Inference across successful replicates

Let \(R_{\mathrm{ok}}\) be successful confirmatory replicates.

- Primary sample: \(\{\Delta_{\mathrm{miss},r}^{\mathrm{L3}}\}\) for \(r \in \mathrm{ok}\).  
- Interval: percentile interval over replicates (not “% of seeds equivalent”).  
- Report failure inventory alongside results.

## 7. Entity-resolution sensitivity (T2-resolved)

### 7.1 Cluster graph

- True entities \(e \in E\), \(|E|=n_{\mathrm{test}}\).  
- Clusters \(c \in C\) from noisy resolution (false **merges** and **splits** as in v2 definitions).  
- Features for T2-resolved are computed on clusters; T3/T4 attributes: **pre-specify** attachment rule:

**Default attachment rule (freeze candidate):**

- KYC/context and watchlist bits live on **true entities** in the DGP.  
- For cluster \(c\), define attribute vector by **max-risk pooling**:  
  - `kyc_tier` = minimum tier (riskiest) among members;  
  - `on_watchlist` = 1 if any member is 1;  
  - continuous attrs = max risk or size-weighted mean (pick one before run; default **max risk** for jurisdiction_risk, **max** prior_sar).  
- This is **semi-oracle attribute attachment** under noisy clusters — label it so; it is not “identity discovery.”

### 7.2 Scoring unit vs evaluation unit

- Model scores **clusters** under T2-resolved.  
- Evaluation labels and MissedPer10k are defined on **true entities**.

### 7.3 Alert budget consumption (normative)

1. Rank clusters by score; consider clusters in decreasing score order.  
2. Maintain a set of **reviewed true entities** \(U\), initially empty.  
3. When cluster \(c\) is selected:  
   - Let \(E(c)\) be true entities with ≥1 wallet in \(c\).  
   - Add all \(e \in E(c)\) to \(U\) (**one cluster alert can cover multiple true entities** — merge case).  
   - Charge **one** unit of alert budget for selecting \(c\), regardless of \(|E(c)|\).  
4. Stop when \(k\) clusters have been selected (budget = \(k\) **cluster alerts**, not entity alerts).  
5. \(\mathrm{TP} = |\{ e \in U : Y_e = 1 \}|\).  
6. If a true entity appears in multiple clusters (split), it is counted in \(U\) at most once; later clusters that only add already-reviewed entities still **consume budget** (duplicate cluster alerts waste budget).

### 7.4 Alternative policy (not default; requires amendment)

Budget charged per **newly covered** entity — more lenient; must not be swapped post hoc.

### 7.5 Oracle baseline

T2-oracle: each cluster = one true entity; budget \(k\) entity alerts; same MissedPer10k definition.

## 15. Claims the eventual manuscript may and may not make

### May make (if protocol completed and results support)

1. Describes a tiered instrument measuring **identity-linked auxiliary information** above **linked behavioural features**.  
2. Reports \(\Delta_{\mathrm{miss}}^{\mathrm{T2}-\mathrm{T4}}\) at a **prespecified** \(k\) on independent test populations of size 10k.  
3. States illustrative or author-justified \(\delta^\*\) **as a policy tolerance**, not a data-mined constant.  
4. If H2 passes: reports DiD evidence that **logistic vs boosted trees differ** in how much auxiliary information reduces misses.  
5. Treats AUC=1 historical failure as methodological contribution.  
6. Labels T2-oracle vs T2-resolved; reports merge/split sensitivity under §7 rules.  
7. Labels T1 max-pool as evaluation benchmark.  
8. States AMLworld/Elliptic cannot validate T3/T4 construct.

### May not make

1. “We measured the value of **civil identity** / raw identity access.”  
2. “Identity access is unnecessary for AML” as a universal claim.  
3. Operational equivalence based only on AUC/AP TOST with δ=0.03.  
4. Equivalence justified by pilot-derived AP margins.  
5. “% of seeds equivalent” as primary inference.  
6. Silent omission of audit/generator failures.  
7. “ZK linkage achieves T2” without selected construction + threat model (architecture doc).  
8. “Anonymity” or protocol security claims without concrete design and proof basis.  
9. “Enacted” H.R. 1919 / law from S. 1124 introduction.  
10. That confirmatory OOF results equal deployment train/test generalisation.
